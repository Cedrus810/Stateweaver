## 1. 结论

**t1 第 0 步的搜索找到了 B，问题不在搜索覆盖。** B 作为 B′ 的近重复被去重并掉，又因为影子"每个保留帧只留 σ 最低的一个"，B′ 唯一的影子槽位给了另一个近重复（+0.8258 mHa），B 没有登记成影子。第 5 步 B 成为最低态时 beam 里没有它，记 WARN。这正是影子设计"未确认"第 4 条写过的风险："若同一个 X 有两个以上真正不同的近重复候选，会漏掉其余的。"

（2026-11-01 上一轮回复和 `state.md` 曾写成"第 0 步搜索根本没有找到 B"，那是只看了登记下来的影子得出的，已更正。）

## 3. 改法

| 编号 | 改什么 | 在 t1 上会怎样 | 代价 / 风险 |
|---|---|---|---|
| **S1 取消单槽位** | 每个保留帧的近重复（σ < `shadow_sv`）全部登记，彼此之间仍按 σ ≥ `shadow_sv` 去重（`beam.py:609` 已有这一检查，只删掉 `best` 的"每帧一个"） | B 和 +0.8258 都登记 → B 按 t2 / t3 的路径晋升 | 第 0 步影子数 3–4 → 5–7（下表）；每个影子每步一次 `cap_near` 短 SCF、最多 5 步；本批之前影子占计算量 2–5%（§4.27），会上升，具体多少未测 |
| S2 已分开的不占槽位 | 登记时 \|ΔE\| > `accept_de`（0.05 mHa）的近重复已经满足影子的"已分开"判据，直接交给准入，不进影子；槽位仍每帧一个 | +0.8258（ΔE 0.137）直接去准入 → 槽位给 B | 第 0 步准入候选变多，容量 3 时竞争变了（t1 里 +0.8258 第 1 步本来也 spawn 了）；同一保留帧有两个**都没分开**的近重复时仍会漏一个 |
| S3 = S1 + S2 | | | 改动面最大 |

第 0 步影子数（S1，重放统计）：

| run | 近重复数 | 现在（每帧一个） | S1 |
|---|---|---|---|
| t0 | 11 | 4 | 7 |

**建议：S1**。理由：直接去掉造成这次失败的那条假设；不改同态判据、准入、合并和验收；代价有上限（受窗口内候选数限制），而且能量化。S2 改的是准入的输入，影响面比 S1 大，又解决不了"两个都没分开"的情况。
